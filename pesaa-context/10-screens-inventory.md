# 10 — Screens inventory

Every `page.tsx` in the three Next.js apps. Generated by walking each page and the components it imports (two levels deep) and matching data hooks in `src/lib/api/hooks.ts` to the API functions in `src/lib/api/*.ts`. Columns:

- **API calls** — endpoints reachable from the page's own code and directly imported components. Shared shell calls (`/tenants/me/current`, entitlements, branches) appear on many pages because the shell components are imported.
- **Load / Empty / Error** — whether the page code (or its direct components) contains a loading state (`PageLoader`, `isLoading`, …), an empty-state branch, and an error branch (`isError`, `role="alert"`, …). This is a static heuristic: "yes" means the code path exists, not that it was visually verified. [Treat as indicative.]
- In paths, `{x}` stands for a path parameter (an id) or a value built at runtime.
- **Responsive** — uses Tailwind breakpoint classes (`sm:`/`md:`/`lg:`); "cards" = uses `TableScroll mobileLayout="cards"` for phones.

Totals: ERP/POS `frontend/` 142 pages, `super-admin/` 59 pages, `website/` 16 pages. The separate `mobile/` app is not covered (see 00-index).

## Dashboard

Route `/dashboard` — `frontend/src/app/(erp)/dashboard/page.tsx` (1,026 lines) + `ModuleBreakdown.tsx`, `DateRangeFilter.tsx`. Visible to the **business owner only** (`ownerOnly` in `frontend/src/lib/navigation.ts`). A period selector (`DateRangeFilter`; default "This month") sets `from`/`to` for the period-aware queries. While any of 7 queries is loading the whole page shows one `PageLoader`.

### Widgets and calculations

| Widget | What it shows | Calculation |
|---|---|---|
| Greeting | "Hello, {first name} 👋" | from signed-in user |
| KPI cards (5) | `{period} Sales`, `{period} Expenses`, `{period} Profit`, `Cash Available`, `Customers` | Sales = income statement `total_revenue`; Expenses = `total_operating_expenses`; Profit = `net_income`; Cash = cash-flow `ending_cash`; Customers = customer list `total` (all-time). Change-vs-previous badges are wired but always `null` (never shown). |
| Module breakdown (4 cards) | Sales by Category, Expenses by Category, Stock Value, Pipeline by Stage | Sales by category: sum `line_total` of order items from the 500 orders whose date is inside the period, category looked up in the first 200 products (missing → "Uncategorized"). Expenses: first page of expenses, filtered by `expense_date` in period, grouped by category. Stock value: `cost × stock` of the 200 products grouped by category (not period-aware). Pipeline: deal `value` grouped by `stage` (not period-aware). |
| Low-stock alert line | "N products are at or below their reorder level" | N = low-stock report total, falling back to products where stock ≤ min_stock (variants summed) |
| Tax deadline line | "Quarterly VAT & CIT instalment due …" | `nextTaxDeadline()` computed in the browser; shown when ≤ 21 days away. Fixed quarterly schedule, not from tax settings [hardcoded rule]. |
| Sales chart | `{period} Sales` — "Revenue vs expenses" | `buildChart()` buckets the 500 orders by hour/weekday/week-of-month/month using `orderBaseTotal`. **Expenses series is always 0.** For preset periods (today/week/month/quarter/year) orders are bucketed by hour-of-day, weekday or month **without checking the date is inside the period**, so older orders leak into the chart; the month view has only Wk 1–4, so days 29–31 are dropped. Custom ranges (`buildRangeChart`) do filter by date. |
| Target & Quick actions | `{period} Target` progress, Earnings breakdown (sales/expenses/profit), 6 quick links: Record Sale (`/sales`), Add Stock (`/inventory`), Record Expense (`/expenses/list`), View Reports (`/accounting`), Customers, Set Target (`/sales/targets`) | target = first sales target whose `period` text contains the period label |
| Recent Sales table | last 5 completed orders: customer, items, total, order #, relative time | from the 10-order query; empty state "No completed orders yet". Order number colored with the **cash** color regardless of payment method. |
| Side panel | Top Products (top 8 by revenue) and Low Stock (6 lowest) | Top products computed from **all 500 orders, not the selected period**. |

Issues in brief: heavy client-side aggregation over capped samples (500 orders / 200 products) gives wrong numbers for larger businesses; several widgets ignore the selected period; previous-period comparisons are never computed.
