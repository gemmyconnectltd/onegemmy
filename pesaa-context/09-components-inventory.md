## Layout and navigation

### ERP shell (`frontend/src/app/(erp)/layout.tsx`)

Renders, in order: `Sidebar` (main nav, `components/dashboard/Sidebar.tsx`) → `Topbar` (`components/dashboard/Topbar.tsx`: `NavigationSearch`, `BranchSwitcher`, `AskPesaaAI`, notifications bell, language, theme, user menu with sign-out) → `<main>` wrapped in `ModuleAvailabilityGuard` (redirects when a module is off or not permitted) → global `UnsavedChangesGuard`, `ActivityTracker` (usage beacons), `SupportFab` (floating help: "Ask Pesaa AI" + WhatsApp chat) and `ProductTour` (first-run tour, `components/tour/ProductTour.tsx`). Module pages add a second sidebar via `ModuleLayout` → `SecondSidebar` (`components/dashboard/`). While auth restores the session the shell shows `PageLoader variant="screen"`.

Sidebar behavior: collapsible; orientation `left | top | big` stored in app config (`frontend/src/lib/appConfig.tsx`); below 1024px it becomes a drawer. Items are filtered by business features (entitlements), module access, permission and `ownerOnly` (`visiblePrimaryNavigation` in `frontend/src/lib/navigation.ts`). Active row = full-width solid primary fill (`pesaa-nav-row` + `data-active`).

## How common UI is built

- **Buttons:** `components/ui/Button.tsx` (both apps) wraps Base UI and reads variants/sizes from the shared `design-system/button.ts` (class-variance-authority). Variants: `default`/`primary` (green, identical), `secondary`, `outline`, `ghost`, `destructive`/`danger` (identical, red tint), `link`; sizes `xs`, `sm` (28/32px), `default` (36/40px), `lg` (40/44px), `icon`, `icon-xs`, `icon-sm`, `icon-lg`. Two pairs of variants are exact aliases.
- **Forms:** `components/ui/Form.tsx` exports `Field` (label + hint + error), `Input`, `Select`, `Textarea`, `FormFooter`. `FormKit.tsx` (ERP) adds `FormSection`, `FormRow`, `FormErrorSummary`, `FormActions`, `FormPage`, `MoneyField`, `FileDropzone`, `focusFirstInvalid`. No form library — plain controlled `useState` + native `required`/`min` + hand-written checks; server errors shown from the mutation error.
- **Overlays:** `Drawer` (left/right/center/bottom, sizes sm/md/lg/xl/document) is the only modal primitive; `ConfirmDialog` / `useConfirmDialog`, `ReasonDialog` build on it.
- **Tables:** raw `<table>` inside `TableScroll` (scroll boundary, optional `mobileLayout="cards"`) or the older `TableWrap` (`ui/Table.tsx`); `TableState` renders loading/error/empty rows; `Pagination`; `BulkActionBar` + `useBulkSelection`. Super-admin has a real `DataTable` + `SortHeader`; the ERP does not.
- **Cards/metrics:** ERP `StatCard`; super-admin `Metric`, `DataCard`.
- **Charts:** Recharts, lazy-loaded through `frontend/src/components/charts/lazy.tsx`; colors from `frontend/src/lib/chartColors.ts`. Super-admin uses Recharts and also `chart.js` (traffic charts).
- **Loading:** single `PageLoader` (`page` / `compact` / `screen`).
- **Imports:** `CsvImportDrawer.tsx` (930 lines) — the 3-step Upload → Review & Fix → Import engine used by every importer.

## Duplicates and inconsistencies

- **Two parallel UI kits.** `frontend/src/components/ui/` and `super-admin/src/components/ui/` both define `Button`, `Drawer`, `ConfirmDialog`, `Field/Input/Select/Textarea/FormFooter`, `Toggle`, `TableScroll`, `PageLoader`, `Pagination`, `BulkActionBar`, `LogoMark` as separate copies (only tokens and button variants are synced by `scripts/sync-design-system.mjs`). They have drifted (e.g. super-admin `Drawer` 6.1 KB vs ERP 7.3 KB; ERP lacks `Badge`, `EmptyState`, `PageHeader`, `DataTable`, `TabStrip`; super-admin lacks `FormKit`, `StatCard`, `SearchSelect`).
- **Same name, different component (ERP):** `StatusBadge` (`accounting/InvoiceDocument.tsx` vs `hr/State.tsx`), `Pill` (`branches/parts.tsx` vs `users/AccessParts.tsx`), `StatusPill` (`branches/parts.tsx` vs `users/ProfileDetails.tsx`), `Toggle` (`mobile/Toggle.tsx` vs `ui/Toggle.tsx`).
- **Same name, different component (super-admin):** `Badge` (`billing/ui.tsx` vs `ui/Badge.tsx`), `StatusPill` (`marketing/shared.tsx` vs `usage/UsageShared.tsx`); chart components duplicated between `charts/TrafficCharts.tsx` and `charts/lazyTraffic.tsx` (lazy wrappers with the same names).
- **Two table wrappers in the ERP:** `TableWrap` (`ui/Table.tsx`) and `TableScroll` (`ui/TableScroll.tsx`) do the same job.
- **Status badges are local per module** (debts, sales, HR, branches, users each have their own) — there is no shared ERP `Badge` with semantic tones.
- **Empty folders** `frontend/src/entities|features|processes|shared|widgets` contain only a placeholder `index.ts` (leftover feature-sliced scaffold).
